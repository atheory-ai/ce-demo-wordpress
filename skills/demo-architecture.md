# CE Demo Architecture

This repository is a reusable demonstration pattern, instantiated with the
WordPress, Gutenberg, and WooCommerce constellation. Its job is to show how a
developer or agent moves from unfamiliar source to a safer decision.

## Select the right mode

- **Baseline:** use `main` and ordinary local inspection only. It establishes
  the cost and quality of reconstructing context from source.
- **CE:** use this branch and CE graph/source tools. Attribute improvements only
  to CE-provided source evidence.
- **CE + Skillex:** activate the relevant procedural skill as well. Attribute
  checklist/process benefits to Skillex, never to CE's indexed facts or IIR.
- **IIR:** use the checked-in TypeScript fixtures. It demonstrates a bounded
  semantic loop, not whole-program or PHP verification.
- **Plugin authoring:** build or scaffold an extension. This demonstrates that
  language and framework knowledge can become reusable compiler inputs.

## Evidence rules

1. State the task, source revision, branch, CE version, plugin hashes, and
   active skills.
2. Distinguish source facts, inferred conclusions, declared intent, and unknown
   conditions.
3. Cite CE results before narrow-reading their underlying source.
4. Treat `partial`, `unsupported`, and `inconclusive` as useful outcomes—not
   as lesser forms of verification success.
5. Use the shared report template. A fair baseline can outperform CE on a
   factual question; record that result.

## Presentation arc

Start with a concrete WordPress problem, show the uncertainty it creates,
retrieve the relevant relationships, show the resulting plan or semantic
artifact, and finish with an evidence-backed next action. Do not begin with a
feature inventory or a claim of universal code understanding.
